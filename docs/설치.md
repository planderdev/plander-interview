# 실제 DB 연결과 배포

## 1. 테이블과 함수 만들기

Supabase 대시보드(프로젝트 `hmjbbdwzwiqihqhjtspd`) → SQL Editor에서 `supabase/migrations/20261029000100_pi_interviews.sql`을 한 번 실행합니다.

만드는 것:

- 테이블 `pi_interviews` (RLS 켜짐)
- 권한 함수 `pi_member_role`, `pi_can_view`, `pi_can_edit`
- 고객 공유 함수 `pi_shared_interview` (로그인 없이 실행 가능, 고른 항목만 반환)
- 의뢰 전환 함수 `pi_convert_interview` (`pw_clients`, `pw_projects`에 1건씩 추가)

웍스 테이블 구조는 바꾸지 않습니다.

## 2. 환경 변수

`.env.example`을 `.env.local`로 복사하고 값을 채웁니다. 값은 웍스 Vercel 프로젝트의 같은 이름 변수에서 가져옵니다.

| 이름 | 값 |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 웍스와 같음 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 웍스와 같음 |
| `NEXT_PUBLIC_WORKS_URL` | 웍스 주소 (전환 뒤 "웍스 프로젝트 열기"에 씀) |

서비스 롤 키는 쓰지 않습니다. 모든 요청은 로그인한 사람의 권한으로 실행됩니다.

## 3. 배포 (Vercel)

1. Vercel에서 `planderdev/plander-interview`를 새 프로젝트로 가져옵니다.
2. 위 환경 변수 세 개를 넣습니다.
3. 웍스처럼 커밋 작성자 제한을 쓰면 같은 규칙을 맞춥니다.

## 4. 연결 뒤 확인할 것

- 팀원 계정으로 로그인해 새 인터뷰를 만들고 저장되는지
- "참석자만" 범위 인터뷰가 다른 팀원에게 보이지 않는지
- 고객 공유 링크를 로그아웃 상태(시크릿 창)에서 열었을 때 고른 항목만 보이는지
- 의뢰 전환 뒤 웍스 클라이언트(상담중)와 프로젝트(대기)가 생기는지
